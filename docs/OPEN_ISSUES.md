# 尚未解决的问题与下一步

## 1. 内容生产还是「半自动」

**现状**：杏花沟的 scenes/endings 基于提取结构人工长肉。`production/generate_world.py` 已把分段提取、场景/结局改写、检查点与内容机检接成可重复的制作命令；网页投书在结构编辑后也走同一条制作与质量报告流程。第三本原创短篇在离线模式下完成结构验收。

**缺口**：
- 真实文本 API 未配置 Key，模型阶段目前只用模拟响应验证，还没有人工评估真实输出
- 本地启发式提取仍会产生占位内容，不能当作已经理解原著
- 内容机检能标出明显空泛和重复，但不能代替人工判断人物口吻与取舍重量

**下一步**：
1. 用授权书稿与真实文本 API 跑一遍 `--llm`，逐幕审阅产出
2. 按 `quality_report.json` 修订对白、代价和延迟回响，再走多路线试玩
3. 将原文受控投喂和公开前去标识化检查做成完整发布门槛

---

## 2. 真实版权书接入

**现状**：原文只在 `source/` 作样本；数据包无原文段落。

**缺口**：
- 受控投喂流程（临时目录、不落日志、不进版本库）未自动化
- 公开分享的去标识化检查清单未做成工具
- 「简单改名不够」需要人工复核清单

**下一步**：
- `production/privacy_check.py`：n-gram 重叠检测、人名地名替换表、输出「可公开 / 需复核」
- 文档化受控制作环境操作步骤

---

## 4. 体验上还偏薄的地方

- 中段（寒露–立冬）选项密度够，但部分 hook 文案仍像「说明」而非「对话」
- 人物多人同时在场时，关系变化不够「分摊」到每个 NPC
- 结局条件靠手工阈值，长线数值可能漂；需要更多台本做校准
- 小雨线写得最重；孙家/宗族/手艺线已补，但陈阿国内心还可以再厚一场
- **扩充后仍待打磨**：单周目只能碰到约一半场景（时间稀缺是设计），需要 3–4 条「专精流」台本覆盖全部分支
- 面子/硬气在极端路线上仍可能贴边（0 或 100）；下一轮用更细的软上限或恢复事件

---

## 5. 明确不打算做的

- 爽文式改写历史
- 靠画面音效补沉浸
- 把单一样本手工剧情说成「投书自动生成」
