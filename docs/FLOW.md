# 从书籍输入到可玩世界

```mermaid
flowchart LR
  A[书籍原文<br/>受控制作环境] --> B[阶段A 结构提取<br/>欲望/阻碍/代价/定数]
  B --> C[阶段B 长出血肉<br/>日常场景与选项]
  C --> D[阶段C 延迟后果<br/>hooks]
  D --> E[阶段D 结局<br/>我成为了谁]
  E --> F[validate.py<br/>假选择/空引用/线索]
  F --> G[package/<br/>world+scenes+endings]
  G --> H[engine 运行时<br/>游玩时零模型]
  H --> I[完整游玩<br/>状态/记忆/结局]
```

## 1. 制作阶段（可以上 AI，受控）

| 阶段 | 输入 | 输出 | 防线 |
|------|------|------|------|
| A 结构提取 | 原文/摘要 | `world_extract.json`：冲突源、人物 wants/blocks/costs、定数+前置线索 | 不复述原文 |
| B 长出血肉 | 结构 JSON | `scenes.json`：「本来可能发生」的日常 | 非原书情节转述 |
| C 延迟后果 | 场景选项 | `hooks`（delay 2–12） | 必须通过具体的人回来 |
| D 结局 | 累积状态 | `endings.json` + epithet | 回答「我成为了谁」 |
| 校验 | 全部 | `validate.py` | 假选择、空引用、定数无线索 |

## 2. 运行阶段（不上 AI，可离线）

`engine/` 只读 `package/`：

- 时间按节气回合推进
- 每回合：风声 → 延迟后果 → 定数 → 场景选择
- 选项改数值/关系/旗标，并写入 `pending` 延迟队列
- 人物通过关系值与记忆文案「记得」玩家
- 结束时按条件表选结局，输出 epithet

## 3. 样本证明

`data/samples/xinghuagou/` 走完了：

原创短篇 → 结构提取 → 场景包 → 校验 → 双线试玩 → 结局分叉

第二本《筒子楼》验证了换书不换引擎；第三本原创短篇位于 `tests/fixtures/nandi/`，由制作命令在临时目录生成并完成双路线验收。

## 4. 当前诚实边界

- 样本的 scenes 是**基于提取结构的人工长肉**，不是「投书一键生成」的黑盒
- 可续跑制作命令、无 Key 草稿的限制和真实版权书的受控投喂边界，见 `docs/PRODUCTION_PIPELINE.md` 与 `docs/OPEN_ISSUES.md`
- **没有**把手工写好的样本剧情冒充自动流水线：本地脚手架保证可玩；模型加厚的真实文本质量仍需有 Key 后逐幕验收
